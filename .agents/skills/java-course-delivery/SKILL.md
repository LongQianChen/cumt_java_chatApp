# Java 聊天课设：规约开发与验证

将当前任务落实为一条可追溯的链路：需求、验收条件、代码变更、验证结果。具体功能和技术约定引用项目文档，本文件只维护可重复使用的工作方法。

## 1．定位本次任务

先明确本次要改变的行为，再查看相关源码、测试、工作区差异和已有开发记录。已有实现从当前状态续做，不重新初始化工程，也不为一个局部任务重跑整套开发流程。

以下路径均相对项目根目录，按需读取对应章节：

| 当前工作 | 读取内容 |
| --- | --- |
| 功能开发、行为调整 | `docs/02-项目设计.md` 中相关需求、交互和协议 |
| 测试、缺陷修复、阶段验收 | `docs/03-验收与开发计划.md` 中对应用例及现有测试代码 |
| 地址绑定、连接配置、网络验收 | `docs/07-IP使用约定.md` 及实际配置、连接实现 |
| 构建、启动、打包 | `README.md` 和现有构建、启动脚本 |
| 记录开发与验证结果 | `docs/05-开发与验证记录模板.md` 中的记录格式及当前工作段记录 |
| 整理报告证据 | `docs/04-报告提纲与证据.md` 中相关章节 |

将用户最新确认的要求与文档、实现对照。已明确的变更同步到对应规格，不让旧文档中的阶段安排覆盖新决定。只有会改变功能含义且无法从现有材料判断的分歧才提出问题。

## 2．先写清可验收行为

把任务对应到现有需求 R 编号和验收 A 编号；既有用例足够时直接复用，不另建重复清单。缺少判定条件时，先在对应规格或验收文档补充：

- **前置条件：**连接状态、参与客户端、会话或数据条件。
- **操作与输入：**具体执行什么，而不是“测试一下功能”。
- **可观察结果：**谁收到什么、界面或文件如何变化、错误如何反馈。
- **失败与不变项：**异常时怎样结束，哪些已有状态必须保留。
- **验证方式：**使用哪个测试入口、命令或人工操作判断。

例如，私聊不能仅验收“发送成功”：甲、乙、丙在线，甲向乙发送一条消息，甲和乙各显示一次，丙既不收到正文也不增加私聊未读；目标离线时返回明确失败，不产生成功回显。由此分别验证路由隔离、显示去重和错误反馈。

新增功能先明确正常路径及关键失败路径；修复缺陷先保留可复现步骤或失败测试，再修改实现。不要用现有错误行为反过来改写预期。

## 3．按行为完成增量实现

从最小可验证单元开始，复用现有模块。只有任务确实涉及多个层次时，才依次处理协议与业务、界面交互、持久化与恢复。

- **协议或路由变更：**同时核对编解码、收发两端、服务端身份来源和错误响应；不能只让一端接受新字段。
- **连接生命周期变更：**覆盖建立、加入、断开、失败和重连；检查旧连接回调、线程及资源是否正确结束。客户端本地绑定与服务端目标地址分别处理，重连保持所选绑定设置。
- **Swing 变更：**网络与文件操作在后台执行，组件更新回到 EDT；状态变化同时更新按钮、提示和可执行操作。
- **历史记录变更：**检查资料隔离、保存、重新加载及损坏处理，避免新功能破坏已有可读数据。

每完成一个行为就运行最相关的检查。失败时先定位原因，再修改并重测，不靠连续改动掩盖故障，也不把无关重构混入当前任务。

## 4．按影响选择回归

局部修改执行直接相关用例及受影响的相邻路径；协议、共享状态或生命周期变更扩大回归范围；阶段交付再执行完整验收集。详细输入、边界值和预期以 `03` 为准。

| 变更对象 | 重点回归 |
| --- | --- |
| 编解码、消息字段 | 分片、多帧、半帧断开、非法长度、坏编码、请求与回显对应 |
| 昵称、群聊、私聊 | 重名拒绝、群聊不重复、三客户端私聊隔离、离线目标、发送者不可伪造 |
| 地址与连接 | 实际本地／远端端点、绑定失败、连接失败、断线禁发、重连、退出释放资源 |
| 会话与界面 | 中文输入和换行、未读增加与清零、历史不计未读、等待时窗口响应 |
| 文件与本地资料 | 重启读取、不同资料隔离、重复打开、损坏或不可写时保留原数据 |
| 构建与启动 | 干净构建、打包后启动、中文及空格路径、多客户端独立运行 |

网络验收核对实际 Socket 端点，并完成应用消息往返。配置查询只证明地址存在，端口连通只证明连接可达，二者都不能代替聊天功能验证。具体地址从项目网络约定和运行配置读取。

核心逻辑优先用现有纯 Java 测试验证；窗口交互使用真实 Swing 窗口检查。无法执行的检查写明缺少的条件，不用代码审阅替代运行结果。测试数据与日常聊天记录分开存放。

## 5．同步规格并留下证据

行为变化更新对应设计和验收条件，启动方式变化更新 README；没有变化的文档不为凑记录而改动。过程与结果续写当前工作段记录，不另抄一份规格。

每项验证记录：对应需求／用例、实际命令或操作、预期、实际结果，以及日志或截图路径。结果区分“通过、失败、未执行”；失败修复后补充重测结果。只保存能解释关键决策、定位问题或证明结果的证据，不以整段对话代替开发记录。

本次任务完成时检查：目标行为已实现，相关回归有结果，必要文档与实现一致。交接只说明改动、实际验证和剩余事项，并给出可复现的运行入口；阶段交付再核对源码、配置、构建产物与使用说明。
